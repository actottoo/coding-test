## 개발 환경 만들기

C++ 코드는 **텍스트 파일**일 뿐이다. CPU가 실행하려면 **컴파일러(g++ 또는 clang++)**가 기계어 실행 파일로 바꿔야 한다. 그래서 필요한 것은 ① 컴파일러 ② 편집기(VS Code) ③ 터미널, 세 개다.

**Windows**

1. https://www.msys2.org 에서 설치 파일을 받아 기본 경로(`C:\msys64`)로 설치한다.
2. 설치 끝에 열리는 **MSYS2 UCRT64** 창에 입력: `pacman -S mingw-w64-ucrt-x86_64-gcc` → 물어보면 Enter.
3. 시작 메뉴에서 "환경 변수" 검색 → **시스템 환경 변수 편집 → 환경 변수 → 사용자 변수의 Path → 편집 → 새로 만들기** → `C:\msys64\ucrt64\bin` 추가 → 확인.
4. **새로** 연 PowerShell에서 `g++ --version` → 버전 숫자가 나오면 성공. (`'g++'은(는) ... 아닙니다`가 나오면 3번을 다시 확인, 그래도 안 되면 노트에서 질문)

## 이론 1 — 컴파일러가 하는 일

`g++ hello.cpp -o hello` 한 줄 안에서는 네 단계가 일어난다. 아키텍처 시간에 본 그림 그대로다.

| 단계 | 입력 → 출력 | 하는 일 | 직접 보는 명령 |
|---|---|---|---|
| 전처리 | `hello.cpp` → `hello.i` | `#include <iostream>`을 그 헤더 파일 **내용으로 통째로 바꿔 끼운다** (수만 줄) | `g++ -E hello.cpp` |
| 컴파일 | `.i` → `.s` | C++ 문장을 **어셈블리**로 (x86이면 x86, RISC-V 컴파일러면 RV 명령어) | `g++ -S hello.cpp` |
| 어셈블 | `.s` → `.o` | 어셈블리를 기계어 비트 패턴으로 | `g++ -c hello.cpp` |
| 링크 | `.o` + 라이브러리 → `hello` | `std::cout` 같은 **남이 만든 함수의 주소**를 이어 붙인다 | (마지막 단계) |

- 실행 파일이 `main`부터 시작하는 이유: 링커가 붙여 주는 시작 코드(crt0)가 준비를 마친 뒤 `main`을 **call**한다. `main`이 `return 0;` 하면 그 0이 a0 레지스터(RISC-V 기준)에 실려 운영체제에게 "정상 종료"로 전달된다.
- **오류 종류 구분**이 중요하다: 세미콜론 빠짐 → *컴파일 에러*(실행 파일이 아예 안 생김). 철자가 맞는데 함수 몸통이 없음 → *링크 에러*(`undefined reference`). 실행은 되는데 답이 틀림 → *논리 오류*(컴파일러가 못 잡는다. 코테에서 대부분은 이것).

## 이론 2 — 출력: cout

> 실행하기 전에 결과를 먼저 예측해 보세요. 예측과 다르면 이 섹션 아래 **질문하기**로 바로 물어보세요.

```cpp
#include <iostream>
using namespace std;

int main() {
    int a = 7;
    cout << "a = " << a << '\n';
    cout << a / 2 << ' ' << a % 2 << endl;
    cout << "끝";
    return 0;
}
```

**트레이스** — `cout`은 화면에 바로 쓰지 않고 먼저 **출력 버퍼**(메모리의 임시 공간)에 모은다.

| 실행한 줄 | a | 출력 버퍼에 쌓인 것 | 화면 |
|---|---|---|---|
| `int a = 7;` | 7 | (비어 있음) | |
| `cout << "a = " << a << '\n';` | 7 | `a = 7⏎` | (아직 없을 수도 있음) |
| `cout << a / 2 << ' ' << a % 2 << endl;` | 7 | `a = 7⏎3 1⏎` → **endl이 버퍼를 비움(flush)** | `a = 7` / `3 1` |
| `cout << "끝";` | 7 | `끝` | |
| `return 0;` | — | 프로그램 종료 시 버퍼가 비워짐 | `끝` 추가 |

정리:

- `<<`는 **왼쪽부터** 하나씩 버퍼에 밀어 넣는다. `cout << x << y`는 `(cout << x) << y`다 — 앞 연산의 결과가 다시 `cout`이라서 계속 이어진다.
- `a / 2`는 **정수 나눗셈**이라 3.5가 아니라 3(소수점 버림), `a % 2`는 나머지 1.
- `'\n'`과 `endl`은 둘 다 줄바꿈이지만 `endl`은 **매번 flush**한다. flush는 운영체제에 쓰기를 요청하는(시스템 콜) 비싼 일이다. 캐시에 모았다가 한 번에 메모리에 쓰는 write-back과 같은 발상 — 줄이 10만 개면 `endl`은 10만 번 시스템 콜이다. **코테에서는 `'\n'`을 쓴다.**
- `using namespace std;`가 없으면 `std::cout`, `std::endl`처럼 써야 한다. 코테에서는 편하게 쓰고, 큰 프로젝트에서는 이름 충돌 때문에 피한다.

**자릿수 맞춰 출력하기** — `<iomanip>`의 `setw`·`setfill`:

```cpp
cout << setfill('0') << setw(2) << 5 << ':' << setw(2) << 30 << '\n';   // 05:30
```

`setfill('0')`은 한 번 정하면 계속 유지되지만, **`setw(2)`는 바로 다음 값 하나에만** 적용된다. 그래서 값마다 `setw`를 다시 쓴다. (C 방식으로는 `printf("%02d:%02d\n", 5, 30);` — 임베디드 C에서 매일 보게 될 형태.)

## 이론 3 — 입력: cin

> 실행하기 전에 결과를 먼저 예측해 보세요. 입력으로 `   12   kim\n 3` 을 넣습니다.

```cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    int n, k;
    string name;
    cin >> n >> name >> k;
    cout << name << ' ' << n + k << '\n';
    return 0;
}
```

**트레이스** — 키보드 입력도 먼저 **입력 버퍼**에 쌓이고, `>>`가 앞에서부터 꺼내 간다. `▲`는 다음에 읽을 위치.

| 실행 | 입력 버퍼 상태 | n | name | k |
|---|---|---|---|---|
| 시작 | `▲   12   kim⏎ 3⏎` | ? | "" | ? |
| `cin >> n` | 앞 공백 3개 건너뜀 → `12` 읽고 공백에서 멈춤: `12▲   kim⏎ 3⏎` | 12 | "" | ? |
| `>> name` | 공백 건너뜀 → `kim` 읽고 줄바꿈에서 멈춤: `kim▲⏎ 3⏎` | 12 | "kim" | ? |
| `>> k` | 줄바꿈·공백 건너뜀 → `3` | 12 | "kim" | 3 |
| 출력 | | | | `kim 15` |

정리:

- `cin >>`는 **공백·탭·줄바꿈을 전부 "구분자"로 보고 건너뛴다.** 그래서 입력이 한 줄로 오든 여러 줄로 오든 같은 코드로 읽힌다. 코테 입력 대부분이 이 성질에 기대고 있다.
- `string`에 `>>`로 읽으면 **공백 전까지 한 단어**만 들어간다. 공백 포함 한 줄 전체는 `getline(cin, s)` (4회차에서 자세히).
- `int`인데 `abc`가 들어오면? `cin`이 실패 상태가 되고 n에는 0이 들어가며 이후 읽기가 전부 멈춘다. 코테는 형식이 보장되므로 걱정하지 않아도 되지만, 임베디드에서 외부 입력(UART 등)을 받을 땐 이 검증이 핵심 일이 된다.
- `int`는 보통 32비트 → 약 **±21억**(2³¹−1 = 2,147,483,647). 그보다 큰 수는 `long long`(64비트). 다음 회차의 주제다.

## 이론 4 — 자주 하는 실수와 빠른 입출력

| 실수 | 증상 | 고치기 |
|---|---|---|
| 출력 형식 불일치 (`Sum:3` vs `Sum: 3`, 마지막 줄바꿈 누락) | 예시는 눈으로 같아 보이는데 "틀렸습니다" | 문제의 출력 예시를 **한 글자씩** 비교. 안내 문구(`"입력하세요: "`)는 절대 출력하지 않는다 |
| `int` 나눗셈을 실수로 기대 | `7/2`가 3 | 실수가 필요하면 `7.0/2` 또는 `(double)a/b` |
| 음수 나눗셈·나머지 | `-7/2`는 −3, `-7%2`는 −1 | C++은 **0 쪽으로 버림**(truncation). 수학의 내림(−4)과 다르다 |
| 컴파일 후 옛 실행 파일 실행 | 고쳤는데 결과가 그대로 | 저장(Ctrl+S) → **다시 컴파일** → 실행, 세 단계를 매번 |

**빠른 입출력 두 줄** — 입력이 수십만 개일 때 시간 초과를 막는 관용구. 지금은 "코테 main 첫 줄에 넣는 주문"으로 기억해 두자.

```cpp
ios::sync_with_stdio(false);   // C의 printf/scanf와 버퍼 동기화를 끔 → cin/cout이 빨라짐
cin.tie(nullptr);              // cin 하기 전마다 cout을 flush하던 것을 끔
```

주의: 이 두 줄을 쓰면 **`cin/cout`과 `scanf/printf`를 섞어 쓰면 안 된다**(출력 순서가 뒤섞임).

**AI에게 질문하는 법 (오늘 끝에 쓸 것)** — AI는 내가 준 맥락만큼만 정확하다. ① 맥락(문제 원문, 내 코드) ② 제약(C++17, 정답 코드 말고 지적만, 입력 범위) ③ 원하는 출력 형식(번호 목록, 경계 사례는 입력 예시로)을 함께 준다.

## 문제 2

**정수 계산기**

두 정수 `a`, `b`가 주어진다. 다섯 줄에 걸쳐 `a+b`, `a-b`, `a*b`, `a/b`(C++ 정수 나눗셈의 몫), `a%b`(C++ 나머지 연산 결과)를 출력하라.

- **입력**: 한 줄에 `a b`
- **출력**: 다섯 줄에 각 결과를 하나씩
- **제한**: `-10000 ≤ a, b ≤ 10000`, `b ≠ 0`

<details><summary>힌트 1</summary>

</details>

## 제출 방법

문제는 사이드바의 **코테 연습장**에서 보고, 코드는 **VS Code**에서 짠다.

1. 연습장 맨 위 **VS Code 연결 설정**에 `coding` 폴더 경로를 한 번 적어 두고, **이번 회차 폴더 내려받기**로 받은 zip을 그 폴더에 푼다.
2. 문제 아래 **VS Code에서 열기**로 `문제N.cpp`를 열어 풀고 저장한다. 파일 맨 위 주석의 걸린 시간·힌트 사용·AI 사용·막힌 점 줄도 채운다. AI 메모는 파일 맨 아래 주석에 쓴다.
3. 다 풀면 세션 채팅에 **「다 풀었어」**라고 쓴다.
   - Claude 데스크톱 앱에 `coding` 폴더를 연결해 두었다면 제가 폴더에서 직접 읽어 g++로 채점한다.
   - 연결하지 않았다면 연습장 문제 아래 **저장한 파일 올리기**에 `.cpp`를 끌어다 놓은 뒤 「다 풀었어」라고 쓴다.
4. 면접 질문 답은 연습장 맨 아래 칸에 쓴다.

- 채점 결과는 연습장의 각 문제 아래에 표시되고, 자세한 해설은 공부 노트에 「채점과 해설」 자료로 올라온다.
- 읽다가 이해 안 되는 부분은 **공부 노트의 해당 섹션 아래 질문하기**로 물어보자(노트는 정답 코드는 알려주지 않는다).
- 설치에서 막혔다면 그것도 막힌 점 줄에 적으면 된다 — 오늘은 환경이 돌아가는 것만으로 절반 성공이다.
