## 이론 1 — 입력 버퍼와 나눗셈, 다시 한 번

> 실행하기 전에 결과를 먼저 예측해 보세요. 입력으로 `  29⏎   -4⏎` (앞에 공백, 두 줄)를 넣습니다. 예측과 다르면 이 섹션 아래 **질문하기**로 바로 물어보세요.

```cpp
int x, y;
cin >> x >> y;
cout << x / y << ' ' << x % y << '\n';
```

| 실행 | 입력 버퍼 (`▲` = 다음 읽을 위치) | x | y | 출력 |
|---|---|---|---|---|
| 시작 | `▲  29⏎   -4⏎` | ? | ? | |
| `cin >> x` | 공백 2개 건너뜀 → `29` 읽고 `⏎`에서 멈춤: `29▲⏎   -4⏎` | 29 | ? | |
| `>> y` | `⏎`·공백 3개 건너뜀 → 부호 `-`까지 숫자로 읽음: `-4▲⏎` | 29 | −4 | |
| `x / y` | 29 ÷ (−4) = −7.25 → **0 쪽으로 버림** → −7 | | | `-7` |
| `x % y` | `x - (x/y)*y` = 29 − (−7)(−4) = 29 − 28 = 1 | | | `-7 1` |

정리 (01회에서 다시 꼭 가져갈 세 가지):

- `cin >>`는 공백·탭·줄바꿈을 **모두 같은 구분자**로 본다. 입력이 한 줄이든 여러 줄이든 같은 코드.
- C++의 `/`는 **0 쪽으로 버림**, `%`는 항상 **`a == (a/b)*b + a%b`**가 성립하도록 정해진다. 그래서 나머지의 부호는 **왼쪽 피연산자(a)를 따른다**: `29 % -4 = 1`, `-29 % 4 = -1`. RISC-V의 `div`/`rem` 명령도 똑같이 정의돼 있다 — C 규칙을 하드웨어가 그대로 지원하는 셈.
- 출력은 버퍼에 모였다가 나간다. 줄바꿈은 `'\n'` (`endl`은 매번 flush → 느림).

## 이론 2 — 16진수로 출력하기: hex, dec, uppercase

임베디드에서는 주소·레지스터 값을 거의 항상 16진수로 본다. `cout`은 `<iomanip>`/`<iostream>`의 **조작자(manipulator)**로 진법을 바꾼다.

> 실행하기 전에 결과를 먼저 예측해 보세요. 특히 세 번째 줄!

```cpp
int a = 255;
cout << a << '\n';               // ①
cout << hex << a << '\n';        // ②
cout << a + 1 << '\n';           // ③
cout << uppercase << a << '\n';  // ④
cout << dec << a << '\n';        // ⑤
```

**트레이스** — `cout`은 내부에 "지금 진법", "대문자 여부" 같은 **상태 플래그**를 들고 있다.

| 줄 | cout의 진법 상태 | 대문자 | 출력 |
|---|---|---|---|
| ① | dec (기본) | 아니오 | `255` |
| ② | `hex`로 바뀜 | 아니오 | `ff` |
| ③ | **여전히 hex** | 아니오 | `100` (256의 16진수) |
| ④ | hex | `uppercase`로 바뀜 | `FF` |
| ⑤ | `dec`로 되돌림 | (대문자 유지, 10진수엔 영향 없음) | `255` |

정리:

- `hex`, `dec`, `uppercase`, `setfill`은 **한 번 켜면 계속 유지(sticky)**된다. 끄거나 되돌리기 전까지 그 뒤의 **모든** 정수 출력에 적용된다. ③이 그 함정이다 — 10진수를 찍으려면 `dec`를 직접 다시 써야 한다.
- 반대로 **`setw`만 다음 값 하나**에만 적용된다(01회 내용). "sticky가 아닌 건 setw 하나"라고 외워 두면 편하다.
- `0x` 접두사는 자동으로 안 붙는다. `"0x"`를 문자열로 직접 출력한다. (`showbase`를 쓰면 붙지만, 0일 때 `0x`가 빠지는 등 모양이 들쭉날쭉해서 코테·로그에서는 직접 쓰는 쪽이 안전.)
- **음수를 hex로 찍으면?** `-4`는 `fffffffc`로 나온다. 32비트 2의 보수 비트 패턴을 그대로 16진수로 읽은 것 — 레지스터에 실제로 들어 있는 값이다. 이건 따라 치기에서 직접 확인한다.
- C 방식: `printf("0x%08X\n", a);` — `%08X`는 "폭 8, 빈칸은 0, 대문자 16진수". 임베디드 C 로그에서 매일 보게 될 줄이다.

## 이론 3 — 오늘 나온 명령어 사전

> 01회 사전(이론 5)에 이어, 오늘 새로 나온 것만.

| 쓰는 모양 | 어디 있나 | 뜻 | 유지되나 | 언제 쓰나 |
|---|---|---|---|---|
| `hex` | `<iostream>` | 이후 정수를 **16진수**(hexadecimal)로 출력 | 계속 | 주소·레지스터 값·비트 패턴 보기 |
| `dec` | `<iostream>` | 이후 정수를 **10진수**(decimal)로 되돌림 | 계속 | `hex`를 쓴 뒤 10진수를 다시 찍을 때 |
| `uppercase` | `<iostream>` | 16진수의 a~f를 **대문자** A~F로 | 계속 | 로그·데이터시트 표기(`0xFF`)에 맞출 때 |
| `"0x"` | — | 그냥 문자열. 16진수라는 표시를 **직접** 찍는 것 | — | 16진수 앞에 항상 |
| `printf("0x%08X\n", a)` | `<cstdio>` | C 방식. `%08X` = 대문자 16진수(X), 폭 8, 빈칸은 0 | — | 임베디드 C 로그 |

"계속"인 것은 꺼 줄 때까지 뒤의 **모든** 정수 출력에 적용된다는 뜻이다. 계속이 아닌 건 `setw` 하나뿐이다.

## AI 활용 단계

두 문제를 **혼자 다 푼 뒤에** 외부 AI에 이렇게 묻는다. 문제 2를 예로:

```
나는 C++ 코딩테스트를 처음 공부하는 학생이야. 아래 문제를 혼자 풀었어.
[문제 2 설명, 출력 형식, 제한 0 ≤ A ≤ 2000000000 을 그대로 붙여넣기]
[내 코드 붙여넣기]
정답 코드를 새로 쓰지 말고, 다음만 번호 목록으로 알려줘:
1) 내 코드가 틀리는 입력이 있다면 그 입력값, 예상 출력, 내 코드의 실제 출력
2) cout의 상태(hex, setfill 등)가 뒤 출력에 남아서 생길 수 있는 문제가 있는지
3) 같은 출력을 printf로 쓴다면 형식 문자열은 무엇인지
```

**AI 답에서 확인할 것**

1. AI가 말한 "실제 출력"을 **직접 실행해서** 비교한다. AI는 코드를 실행하지 않고 머릿속으로 추측하는 경우가 많다 — 다르면 AI가 틀린 것이고, 그게 바로 기록할 거리다.
2. AI가 "A+4가 int 범위를 넘을 수 있다"고 하면, 제한의 최댓값 2,000,000,004가 `int` 최대 2,147,483,647보다 큰지 작은지 직접 계산해 확인한다. (범위 밖을 걱정하면 "애매한 지적")
3. AI가 준 `printf` 형식 문자열을 실제로 넣어 돌려서, `cout` 출력과 글자 하나까지 같은지 본다.

문제는 사이드바의 **코테 연습장**에서 보고, 코드는 **VS Code**에서 짠다.

1. VS Code로 연 **coding-test 저장소 폴더**에 이번 회차 폴더 `coding-02-입출력복습`을 넣는다 (연습장 **이번 회차 폴더 내려받기** zip을 풀거나, 채팅으로 받은 파일을 넣기).
2. VS Code에서 `문제N.cpp`를 열어 풀고 저장한다. 파일 맨 위 주석의 걸린 시간·힌트 사용·AI 사용·막힌 점 줄을 채우고, AI 메모는 파일 맨 아래 주석에 쓴다.
3. **소스 제어**에서 커밋(메시지 예: `02회 문제1 동전 거스름돈 풀이`) → **변경 내용 동기화**. 문제마다 따로 커밋하면 더 좋다.
4. 세션 채팅에 **「다 풀었어」** → 제가 GitHub에서 읽어 g++로 채점한다. (01회 문제를 같이 푸시했으면 그것도 함께 채점)
5. 면접 질문 답은 연습장 맨 아래 칸에 쓴다.

- 푸시를 못 한 날은 연습장 문제 아래 **저장한 파일 올리기**에 `.cpp`를 끌어다 놓고 「다 풀었어」.
- 채점 결과는 연습장의 각 문제 아래에, 자세한 해설은 공부 노트의 「채점과 해설」 자료로 올라온다.
- 읽다가 이해 안 되는 부분은 **공부 노트의 해당 섹션 아래 질문하기**로 물어보자(노트는 정답 코드는 알려주지 않는다). 설치나 커밋에서 막혔다면 그것만 적어도 충분하다.
