## 이론 1 — 자료형은 "정해진 크기의 상자"

> 실행하기 전에 결과를 먼저 예측해 보세요. 특히 마지막 줄! 예측과 다르면 아래 예측 칸에 적거나 공부 노트 이 섹션 아래 **질문하기**로 바로 물어보세요.

```cpp
char c = 'A';
bool ok = true;
int n = 7;
long long big = 3000000000LL;
double d = 2.5;
cout << sizeof(c) << ' ' << sizeof(ok) << ' ' << sizeof(n) << ' ' << sizeof(big) << ' ' << sizeof(d) << '\n';
cout << c << ' ' << ok << ' ' << n << ' ' << big << ' ' << d << '\n';
int bad = 3000000000;
cout << bad << '\n';
```

**트레이스** — 변수를 선언하면 컴파일러가 메모리(스택)에 그 크기만큼 칸을 잡는다.

| 줄 | 잡히는 칸 | 들어가는 비트(값) | 비고 |
|---|---|---|---|
| `char c = 'A'` | 1바이트 | `0x41` (65) | 글자도 결국 **숫자**(아스키 코드) |
| `bool ok = true` | 1바이트 | `1` | `cout`은 `1`/`0`으로 찍는다 |
| `int n = 7` | 4바이트 | `0x00000007` | |
| `long long big = 3000000000LL` | 8바이트 | 30억 | `LL` = "이 숫자는 long long" 표시 |
| `double d = 2.5` | 8바이트 | IEEE 754 부동소수점 | 정수와 비트 모양이 전혀 다르다 |
| `int bad = 3000000000` | 4바이트 | 30억의 **아래 32비트만** | 위쪽 비트가 잘려 나감 |

실제 출력(직접 실행해 확인, WSL Ubuntu g++ 13):

```text
1 1 4 8 8
A 1 7 3000000000 2.5
-1294967296
```

마지막 줄이 함정이다. 30억은 `int`(최대 약 21억)에 안 들어가서 **아래 32비트만 남고**, 그 비트를 2의 보수로 읽으니 음수가 됐다. 그리고 `g++ -Wall`은 이 줄에 **경고도 안 했다**. 컴파일러가 막아 주지 않으니, **"이 값이 상자에 들어가나?"는 내가 계산해야 한다.**

**코테에서 외울 범위**

| 자료형 | 크기 | 범위 | 기억법 |
|---|---|---|---|
| `int` | 4바이트 | −2,147,483,648 ~ 2,147,483,647 | **약 ±21억 (2×10⁹)** |
| `unsigned int` | 4바이트 | 0 ~ 4,294,967,295 | 약 43억 (2³²−1) |
| `long long` | 8바이트 | 약 ±9.2×10¹⁸ | **약 ±9×10¹⁸** |

**아키텍처로 연결하면**: RV32의 레지스터가 32비트라 `int`가 32비트인 게 자연스럽다. `long`은 플랫폼마다 다르다(RV32·Windows는 4바이트, RV64·x86-64 리눅스는 8바이트). 그래서 코테에서는 **항상 8바이트가 보장되는 `long long`**을 쓴다. 판단 기준: 값이나 **중간 계산**이 10⁹(10억)을 넘을 수 있으면 `long long`.

## 이론 2 — 정수 오버플로: 상자가 넘치면

> 실행하기 전에 결과를 먼저 예측해 보세요. `a + 1`은 몇일까? `x * y`는 정말 100억일까?

```cpp
int a = INT_MAX;                  // ① 2147483647
a = a + 1;                        // ②
int x = 100000, y = 100000;
long long p1 = x * y;             // ③
long long p2 = 1LL * x * y;       // ④
unsigned int t = 3;
t = t - 5;                        // ⑤
```

| 줄 | 계산이 일어나는 상자 | 비트 (32비트, 앞부분) | 결과 |
|---|---|---|---|
| ① | — | `0111 1111 … 1111` | 2147483647 |
| ② | `int` + `int` → **int** | `1000 0000 … 0000` (맨 위 비트로 올림) | **−2147483648** |
| ③ | `int` × `int` → **int** 안에서 계산 → 넘친 뒤에 long long에 담김 | 100억의 아래 32비트 | **1410065408** |
| ④ | `1LL`(long long) × int → **long long**으로 계산 | 64비트 안에 여유 있음 | 10000000000 ✅ |
| ⑤ | `unsigned` − → 0 아래로 내려가면 **2³²를 더한 값**으로 돈다 | `1111 … 1110` | 4294967294 |

정리:

- **③이 코테 오버플로 1위 실수다.** "담는 변수가 `long long`이니 괜찮겠지"가 아니다. C++은 **오른쪽 식을 먼저, 피연산자 자료형으로** 계산한 뒤 결과를 담는다. `int × int`는 int 상자 안에서 이미 넘친다. 해결: 피연산자 하나를 먼저 `long long`으로 만든다 — `1LL * x * y` 또는 `(long long)x * y`. 처음부터 `long long x, y;`로 받는 것이 가장 안전하다.
- **signed(`int`) 오버플로는 "정의되지 않은 동작(UB)"**이다. 지금 컴퓨터에선 ②처럼 비트가 넘어가 음수가 되지만, 표준은 그걸 보장하지 않는다(최적화 때 컴파일러가 "넘치지 않는다"고 가정하고 코드를 바꿔 버릴 수 있다). 그러니 "넘쳐서 음수 되는 걸 이용"하면 안 된다.
- **unsigned 오버플로는 정의돼 있다**: 결과는 항상 **2³²로 나눈 나머지**(모듈러 산술). ⑤처럼 0 아래로 가면 위로 돌아온다(wrap-around). 임베디드 타이머 카운터가 정확히 이렇게 동작한다 — 문제 2.
- **아키텍처로 연결하면**: RISC-V `add`는 오버플로가 나도 **아무 신호도 안 낸다**. x86의 OF(overflow flag) 같은 플래그 레지스터가 아예 없다. 비트는 그냥 아래 32비트(RV32)만 남는다. 그래서 오버플로 검사는 소프트웨어(분기 명령)로 해야 하고, C 표준도 "signed 넘침은 네 책임"이라고 정해 둔 것이다.
- 시간복잡도 관점에서 자료형은 속도에 거의 영향 없다(64비트 CPU에서 `long long` 덧셈도 명령 1개). 코테에서는 **고민되면 `long long`**.

## 이론 3 — 형 변환: 나눗셈·char·unsigned로 다시 읽기

> 실행하기 전에 결과를 먼저 예측해 보세요. 다섯 줄 모두!

```cpp
int x = 7, y = 2;
cout << x / y << '\n';                          // ①
cout << x / 2.0 << '\n';                        // ②
cout << static_cast<double>(x) / y << '\n';     // ③
char c = 'A';
cout << c + 1 << '\n';                          // ④
cout << static_cast<char>(c + 1) << '\n';       // ⑤
```

| 줄 | 피연산자 자료형 | 실제 계산 | 출력 |
|---|---|---|---|
| ① | int / int | 정수 나눗셈(0 쪽으로 버림, 01회) | `3` |
| ② | int / **double** | 작은 쪽(int)이 double로 **자동 변환** → 실수 나눗셈 | `3.5` |
| ③ | **double** / int | `x`를 먼저 double로 바꿔 둠 | `3.5` |
| ④ | char + int | char가 **int로 올라감**(정수 승격) → 65 + 1 | `66` |
| ⑤ | int → char | 66을 char로 바꿔 찍음 | `B` |

규칙은 하나다: **두 피연산자 자료형이 다르면 "더 큰(넓은)" 쪽으로 맞춘 뒤 계산한다**(char·bool·short → int → long long → double 순서). 이론 2의 `1LL * x`도 같은 규칙이다.

- `static_cast<자료형>(값)` = "이 값을 이 자료형으로 바꿔라"를 **명시적으로** 쓰는 C++ 방식. C 방식 `(double)x`도 같은 일을 하지만, C++ 코드에서는 무엇을 하는지 드러나는 `static_cast`를 권장한다.
- **같은 비트, 다른 해석**: `static_cast<unsigned int>(-4)`는 비트를 그대로 두고 **unsigned로 다시 읽는다** → `4294967292`(= 2³² − 4). 02회 따라 치기에서 `-4`가 hex로 `fffffffc`로 보였던 것과 같은 비트다. 레지스터 하나에 든 32비트를 `-4`로 보느냐 `0xFFFFFFFC`로 보느냐 `4294967292`로 보느냐는 **해석의 차이**일 뿐 — 문제 3.
- 자주 하는 실수: 평균을 `sum / n`으로 구하면 정수 나눗셈이 된다. 실수 결과가 필요하면 `static_cast<double>(sum) / n`.

> **02회 다시 짚기 (sticky)** — 02회 예측 칸에서 "hex를 위 줄에만 써서 아래 줄은 10진수일 줄 알았다"고 했다. `hex`·`uppercase`·`setfill`은 `cout`의 스위치를 돌려 놓는 명령이라 **`dec`로 되돌리기 전까지 계속** 유지된다. 오늘 문제 3에서 한 번 더 확인한다.

## 이론 4 — 오늘 나온 명령어 사전

> 01회(이론 5)·02회(이론 3) 사전에 이어, 오늘 새로 나온 것만.

| 쓰는 모양 | 어디 있나 | 뜻 | 언제 쓰나 / 주의 |
|---|---|---|---|
| `char c = 'A';` | 기본 자료형 | 1바이트 정수. 글자 한 개(아스키 코드)를 담음 | 작은따옴표 `'A'` = 글자 하나, 큰따옴표 `"A"` = 문자열(다른 것!) |
| `bool ok = true;` | 기본 자료형 | 참/거짓. `true`=1, `false`=0 | 조건문(04회)에서 본격 사용. `cout`은 `1`/`0`으로 찍음 |
| `long long` | 기본 자료형 | 8바이트 정수 (약 ±9×10¹⁸) | 값·중간 계산이 10⁹를 넘을 수 있으면. `cin >>`도 그대로 됨 |
| `unsigned int` | 기본 자료형 | 4바이트, 음수 없는 정수 (0~2³²−1). 넘치면 2³²로 돌아옴 | 비트 패턴·카운터·주소. 음수와 섞어 계산하면 함정 |
| `double` | 기본 자료형 | 8바이트 실수 (IEEE 754) | 소수점 계산. 코테에선 오차 때문에 꼭 필요할 때만 |
| `3000000000LL`, `1LL` | 리터럴 접미사 | 숫자 뒤 `LL` = 이 숫자는 long long. (`2.0`처럼 점이 있으면 double, `5u`는 unsigned) | `1LL * x * y` — 곱셈을 long long으로 시작 |
| `sizeof(x)` | 연산자(헤더 필요 없음) | 변수·자료형이 차지하는 **바이트 수** | `sizeof(int)` → 4. 플랫폼 확인용 |
| `#include <climits>` | 표준 헤더 | **C** 언어 **limits**(한계값) 상수 모음 | `INT_MAX` 등을 쓸 때. 빠뜨리면 `'INT_MAX' was not declared` |
| `INT_MAX` / `INT_MIN` | `<climits>` | int 최댓값 2147483647 / 최솟값 −2147483648 | 범위 확인, "아주 큰 값"으로 초기화할 때 |
| `UINT_MAX` / `LLONG_MAX` | `<climits>` | unsigned int 최댓값 4294967295 / long long 최댓값 | |
| `#include <bitset>` | 표준 헤더 | 비트 묶음(bit set)을 다루는 도구 | 비트 모양을 눈으로 볼 때 |
| `bitset<32>(a)` | `<bitset>` | `a`의 아래 32비트를 `0`/`1` 32글자로 보여 줌 | 디버깅용. `<8>`이면 8비트만 |
| `static_cast<T>(x)` | C++ 키워드 | `x`를 자료형 `T`로 변환 (**static** = 컴파일 시간에 정해지는 **cast**(변환)) | `static_cast<double>(x)`, `static_cast<unsigned int>(-4)` |
| `(long long)x` | C 스타일 변환 | 위와 같은 일, C 문법 | 임베디드 C 코드에서 자주 봄. C++에선 `static_cast` 권장 |
| `-fsanitize=undefined` | g++ 옵션 | 실행 중 **UB**(정의되지 않은 동작: signed 오버플로 등)를 잡아 `runtime error`로 알려 줌 | 오버플로 의심될 때 컴파일 옵션에 추가. 문제 탭 맨 위 「터미널로 풀기」 |

## 따라 치기 예제

1. coding-test 저장소에 이번 회차 폴더 `coding-03-자료형과오버플로`를 넣고(연습장 zip), 그 안에 새 파일 `practice.cpp`를 만들어 **직접 타이핑** → Ctrl+S.

```cpp
#include <iostream>
#include <climits>
#include <bitset>
using namespace std;

int main() {
    int a = INT_MAX;
    cout << "a     = " << a << '\n';
    cout << "bits  = " << bitset<32>(a) << '\n';
    a = a + 1;
    cout << "a+1   = " << a << '\n';
    cout << "bits  = " << bitset<32>(a) << '\n';

    int x = 100000, y = 100000;
    long long p1 = x * y;
    long long p2 = 1LL * x * y;
    cout << "x*y   = " << p1 << '\n';
    cout << "1LL*  = " << p2 << '\n';

    unsigned int t = 3;
    t = t - 5;
    cout << "3u-5  = " << t << '\n';
    return 0;
}
```

2. 터미널(Ctrl+`): `cd ~/coding-test/coding-03-자료형과오버플로`
3. 컴파일·실행 한 번에: `g++ -std=c++17 -Wall practice.cpp -o practice && ./practice`
4. **예상 출력** (직접 실행해 확인):

```text
a     = 2147483647
bits  = 01111111111111111111111111111111
a+1   = -2147483648
bits  = 10000000000000000000000000000000
x*y   = 1410065408
1LL*  = 10000000000
3u-5  = 4294967294
```

5. 두 번째·네 번째 줄을 비교해 **어느 비트가 바뀌었는지** 한 문장으로 말해 본다. (힌트: 맨 왼쪽 비트 = 부호 비트)
6. 이번엔 `-fsanitize=undefined`를 붙여 다시 컴파일·실행해 본다: `g++ -std=c++17 -Wall -fsanitize=undefined practice.cpp -o practice && ./practice` — `runtime error`가 **몇 번, 몇 번째 줄**에서 나는지 먼저 예측. 왜 `3u-5` 줄에서는 안 나는지도 생각해 본다(이론 2 정리 셋째 줄).

## 터미널로 풀기 — 오버플로 잡는 옵션 -fsanitize=undefined

기본 순서(컴파일 → 실행 → 예상과 비교 → `cerr`로 값 찍기)는 **가이드 탭 3·4번** 그대로다. 오늘은 하나만 추가한다: 오버플로는 **에러 없이 이상한 숫자만** 나와서 `cerr`로 찍어도 "입력은 맞는데 결과만 이상한" 상태가 된다. 이럴 때 컴파일 옵션에 `-fsanitize=undefined`를 붙이면 넘친 **줄과 칸**을 실행 중에 알려 준다.

일부러 틀린 예제 — 두 수를 `int`로 받아 더하기·빼기·곱하기(`w1.cpp`):

```cpp
#include <iostream>
using namespace std;
int main() {
    int a, b;
    cin >> a >> b;
    cerr << "[확인] a=" << a << " b=" << b << '\n';
    cout << a + b << '\n' << a - b << '\n' << a * b << '\n';
    return 0;
}
```

```text
$ g++ -std=c++17 -Wall w1.cpp -o w1 && echo 1000000000 1000000000 | ./w1
[확인] a=1000000000 b=1000000000      ← 입력은 제대로 읽었다
2000000000
0
-1486618624                           ← 10¹⁸이어야 하는데? 에러 메시지는 없다
```

`cerr`로 보니 **입력은 맞다** → 계산에서 넘친 것. 어느 계산인지 옵션으로 확인:

```text
$ g++ -std=c++17 -Wall -fsanitize=undefined w1.cpp -o w1 && echo 1000000000 1000000000 | ./w1
[확인] a=1000000000 b=1000000000
w1.cpp:7:56: runtime error: signed integer overflow: 1000000000 * 1000000000 cannot be represented in type 'int'
2000000000
0
-1486618624
```

- 읽는 법: `w1.cpp:7:56` = 7번째 줄 56번째 칸(`a * b`의 `*`), `1000000000 * 1000000000 cannot be represented in type 'int'` = "이 곱은 int에 안 들어간다". → 이론 2 ③의 실수.
- 더하기 `2000000000`은 int 최대(2147483647)보다 작아서 **안 넘쳤다** — 그래서 경고도 곱셈 하나뿐. "어디서 넘치는지"는 최댓값을 넣어 계산해 보면 안다.
- 출력을 파이프(`|`)로 넘기면 `runtime error` 줄이 정답 줄보다 **먼저** 보일 수 있다(`cerr`는 바로, `cout`은 모았다가 나가서). 순서는 신경 쓰지 말고 **줄 번호**를 본다.
- `-fsanitize=undefined`는 **signed** 오버플로만 잡는다. `unsigned`는 넘치는 게 정상 동작이라 조용하다.
- 고친 뒤에는 옵션 없이 평소 명령으로 다시 확인하고 커밋한다(옵션은 확인용 — 느려지고, 채점 환경과도 다르다).

## 문제 2

**타이머 경과 시간 (임베디드 단골)**

MCU에 1ms마다 1씩 오르는 **32비트 unsigned** 틱 카운터가 있다. 4294967295(2³²−1) 다음에는 0으로 돌아간다(wrap-around). 어떤 작업의 시작 시각 틱 `s`와 끝 시각 틱 `e`가 주어질 때 **경과 시간(ms)**을 출력하라. 작업 시간은 2³² ms(약 49.7일)보다 짧다고 가정한다. 즉 `e`가 `s`보다 작으면 그 사이에 카운터가 한 번 0으로 돌아간 것이다.

- **입력**: 정수 `s`, `e` (공백으로 구분)
- **출력**: 경과 시간(ms) 한 줄
- **제한**: `0 ≤ s, e ≤ 4294967295`

| 입력 | 출력 |
|---|---|
| `100 350` | `250` |
| `4294967290 5` | `11` |
| `0 4294967295` | `4294967295` |

두 번째 예시: 4294967290 → …95(5ms) → 0(6ms) → … → 5(11ms).

<details><summary>힌트 1</summary>

입력 범위 `0 ≤ s, e ≤ 4294967295`가 딱 맞게 들어가는 자료형이 이론 1 표에 있다. `int`로 받으면 `4294967290`이 어떻게 읽히는지 직접 해 보라(`echo 4294967290 5 | ./p2`).

</details>

<details><summary>힌트 2</summary>

이론 2 ⑤: `3 - 5`를 unsigned로 계산하면 `−2`가 아니라 `2³² − 2`가 됐다. 이 "자동으로 2³²를 더해 주는" 성질을 `e - s`에 쓰면 조건문 없이 된다. (`long long`으로 받아 풀 수도 있지만, 그럼 음수가 나오는 경우를 따로 처리해야 한다 — 아직 조건문은 안 배웠다.)

</details>

### 🔧 문제 2 터미널로 확인하기

```
g++ -std=c++17 -Wall 문제2.cpp -o p2 && echo 100 350 | ./p2    # 기대: 250
echo 4294967290 5 | ./p2                                       # 기대: 11
echo 0 4294967295 | ./p2                                       # 기대: 4294967295
echo 7 7 | ./p2                                                # 경계(같은 틱): 0
echo 4294967295 0 | ./p2                                       # 경계(딱 한 번 넘어감): 1
```

- `-4294967285`처럼 **음수**가 나오면 → 계산하는 상자가 signed다. `cerr << "[확인] s=" << s << " e=" << e << '\n';`로 입력 값 자체는 맞는지 먼저 본다.
- 결과가 `-2147483647`처럼 엉뚱하면 → `cerr`로 찍어 본다. `[확인] s=2147483647 e=0`이 보이면 입력을 받는 순간 `int`에 안 들어가 **최댓값으로 막히고**, 그 뒤 `e`는 읽기 실패로 0이 된 것이다(직접 실행해 확인한 결과). 받는 자료형을 다시 본다.
