## 이론 1 — 03회 한 장 요약: 계산하는 "상자"가 결과를 정한다

> 실행하기 전에 결과를 먼저 예측해 보세요. 네 줄 모두! 예측과 다르면 아래 예측 칸에 적거나 공부 노트 이 섹션 아래 **질문하기**로 바로 물어보세요.

```cpp
int w = 1500000000, h = 2;
cout << w * h << '\n';          // ①
cout << 1LL * w * h << '\n';    // ②
long long s = w + w;            // ③
cout << s << '\n';
unsigned int u = 0;
u = u - 1;                      // ④
cout << u << '\n';
```

**트레이스** — 핵심은 "오른쪽 식이 **어떤 자료형으로** 계산되나"다.

| 줄 | 피연산자 | 계산되는 상자 | 진짜 값 | 출력 |
|---|---|---|---|---|
| ① | int × int | **int** (32비트) | 30억 → int 최대 21억 초과 | `-1294967296` |
| ② | **long long** × int × int | long long (64비트) | 30억 | `3000000000` |
| ③ | int + int | **int** 안에서 먼저 넘침 → 그 뒤 long long에 담김 | 30억 | `-1294967296` |
| ④ | unsigned − int | unsigned (2³²로 나눈 나머지) | −1 → 2³² − 1 | `4294967295` |

실제 출력(직접 실행해 확인, g++ 13):

```text
-1294967296
3000000000
-1294967296
4294967295
```

**외울 것 세 줄**

1. `int` 최대 ≈ **21억(2.1×10⁹)**, `long long` ≈ 9×10¹⁸. 값이나 **중간 계산**이 10⁹을 넘을 수 있으면 `long long`.
2. ③처럼 **담는 변수가 long long이어도 소용없다.** C++은 오른쪽 식을 피연산자 자료형으로 먼저 계산한다. → 처음부터 `long long`으로 받거나 `1LL *`로 시작.
3. **signed 넘침 = UB**(정의 안 된 동작, `-fsanitize=undefined`가 잡아 줌), **unsigned 넘침 = 정의됨**(항상 2ⁿ으로 나눈 나머지 — 03회 문제 2의 타이머).

> 아키텍처로 연결하면: RV32 `add`/`mul`은 결과의 **아래 32비트만** 레지스터에 남기고 아무 신호도 안 낸다. ①·③의 음수는 그 "아래 32비트"를 2의 보수로 읽은 값이다.

## 이론 2 — 크기가 이름에 박힌 자료형: uint8_t · uint32_t

> 실행하기 전에 결과를 먼저 예측해 보세요. 특히 ②와 ④!

임베디드 C 코드(레지스터 정의, 통신 프로토콜, 펌웨어)는 `int` 대신 **`uint8_t`, `uint16_t`, `uint32_t`**를 쓴다. `int`의 크기는 플랫폼마다 다를 수 있지만(16비트 MCU에선 `int`가 2바이트), 이 자료형들은 **이름에 비트 수가 박혀 있어서 어디서나 같다**. `u` = unsigned, 숫자 = 비트 수, `_t` = type.

```cpp
#include <cstdint>              // uint8_t 같은 고정 폭 자료형이 여기 있다
uint8_t a = 250;
a = a + 10;
cout << static_cast<int>(a) << '\n';                            // ①
uint8_t p = 5, q = 10;
cout << p - q << '\n';                                          // ②
cout << static_cast<int>(static_cast<uint8_t>(p - q)) << '\n';  // ③
uint8_t k = 65;
cout << k << '\n';                                              // ④
```

| 줄 | 무슨 일이 생기나 | 출력 |
|---|---|---|
| ① | 250 + 10 = 260 → 8비트 상자(0~255)에 담으면서 **256으로 나눈 나머지** → 4 | `4` |
| ② | `uint8_t`끼리 빼도 계산 전에 **int로 올라간다**(정수 승격, 03회 이론 3의 `c + 1`과 같은 규칙) → int 계산 5 − 10 | `-5` |
| ③ | 그 −5를 다시 `uint8_t` 상자에 넣으면 256을 더한 값으로 돈다 → 251 | `251` |
| ④ | `uint8_t`는 사실 `unsigned char`의 다른 이름이라 `cout`이 **글자**로 찍는다 (65 = 'A') | `A` |

실제 출력(직접 실행해 확인):

```text
4
-5
251
A
```

정리:

- **8비트 카운터도 32비트 타이머와 원리가 같다**: 넘치면 2⁸ = 256으로 나눈 나머지. 다만 계산 중에 int로 올라가므로, **결과를 다시 `uint8_t`로 담거나 바꿔야** 돈다(②와 ③의 차이).
- `uint8_t`를 `cout`으로 숫자로 보려면 `static_cast<int>(…)`로 바꿔 찍는다(④ 함정).
- **입력도 함정이다**: `uint8_t x; cin >> x;`에 `200`을 넣으면 **글자 '2' 한 개**만 읽어서 x = 50('2'의 아스키 코드)이 된다(직접 실행해 확인). 0~255 숫자를 입력받을 땐 **`int`로 받는다**.
- 코테에서는 보통 `int`·`long long`이면 충분하다. `uint8_t`는 "임베디드 코드에서 이런 게 보이면 이렇게 동작한다"를 알아 두는 용도 — 면접 단골이다.

## 이론 3 — 오늘 나온 명령어 사전

> 01회(이론 5)·02회(이론 3)·03회(이론 4) 사전에 이어, 오늘 새로 나온 것만.

| 쓰는 모양 | 어디 있나 | 뜻 | 언제 쓰나 / 주의 |
|---|---|---|---|
| `#include <cstdint>` | 표준 헤더 | **C** 언어 **std**(standard) **int** 자료형 모음 — 크기가 정해진 정수형들 | `uint8_t` 등을 쓸 때. 빠뜨리면 `'uint8_t' was not declared` (환경에 따라 `<iostream>`만으로 될 때도 있지만 믿지 말고 쓴다) |
| `uint8_t` | `<cstdint>` | 부호 없는 **8**비트 정수 (0~255) | 바이트 데이터·레지스터·시퀀스 번호. `cout`은 글자로 찍고 `cin`은 글자 하나만 읽음 → `static_cast<int>`·`int`로 받기 |
| `uint16_t` / `uint32_t` | `<cstdint>` | 부호 없는 16비트(0~65535) / 32비트(0~4294967295) | 32비트 타이머·주소 = `uint32_t` (03회 문제 2의 `unsigned int`와 같은 크기) |
| `int32_t` / `int64_t` | `<cstdint>` | 부호 있는 32비트 / 64비트 정수 | `int64_t`는 `long long`과 같은 크기(8바이트) |
| `static_cast<uint8_t>(식)` | C++ 키워드 (03회) | 식의 값을 8비트 상자에 넣음 → 256으로 나눈 나머지로 돈다 | 정수 승격된 결과를 다시 8비트로 "돌릴" 때 |
| 정수 승격 (integer promotion) | 언어 규칙 | `char`·`uint8_t`·`short`·`bool`은 계산 전에 **int로 올라간다** | `uint8_t` 두 개를 빼도 결과는 int — 음수가 나올 수 있다 |

## 문제 1

**센서 보드 둘레와 넓이**

직사각형 기판의 가로 `w`, 세로 `h`(단위 μm)가 주어진다. 둘레 `2 × (w + h)`와 넓이 `w × h`를 각각 한 줄에 출력하라.

- **입력**: 정수 `w`, `h` (공백으로 구분)
- **출력**: 두 줄 — 둘레, 넓이
- **제한**: `1 ≤ w, h ≤ 1000000000`

| 입력 | 출력 |
|---|---|
| `3 4` | `14`<br>`12` |
| `1000000000 1000000000` | `4000000000`<br>`1000000000000000000` |
| `1 1000000000` | `2000000002`<br>`1000000000` |

</details>

<details><summary>힌트 2</summary>

## 문제 2

**8비트 시퀀스 번호 (CAN·UART 통신 단골)**

차량 ECU끼리 주고받는 패킷에는 **8비트 시퀀스 번호**가 붙는다. 0, 1, 2, …, 255 다음은 다시 0이다. 마지막으로 받은 패킷 번호 `p`와 지금 받은 패킷 번호 `c`가 주어질 때, **번호가 몇 칸 앞으로 갔는지**(0~255)를 출력하라. 255칸보다 많이 건너뛰는 일은 없다고 가정한다.

- **입력**: 정수 `p`, `c` (공백으로 구분)
- **출력**: 앞으로 간 칸 수 한 줄
- **제한**: `0 ≤ p, c ≤ 255`

| 입력 | 출력 |
|---|---|
| `10 13` | `3` |
| `250 4` | `10` |
| `0 255` | `255` |

두 번째 예시: 250 → 251 → … → 255(5칸) → 0(6칸) → … → 4(10칸).

<details><summary>힌트 1</summary>

03회 문제 2(32비트 타이머)와 같은 문제를 **8비트**로 줄인 것이다. "넘치면 256으로 나눈 나머지"(이론 2 정리 첫 줄). 단, 입력은 무엇으로 받아야 할까? (이론 2 정리 셋째 줄)

</details>

<details><summary>힌트 2</summary>

방법은 두 가지다. ① `c - p`가 음수일 수 있으니 **256을 더한 뒤 256으로 나눈 나머지**를 구한다(`%`는 01회). ② 이론 2의 ③처럼 차이를 `uint8_t` 상자에 넣어 돌린다 — 이때는 출력할 때 ④ 함정을 조심. 둘 다 조건문 없이 된다.

</details>

### 🔧 문제 2 터미널로 확인하기


- `-246`처럼 **음수**가 나오면 → 계산이 int로 끝났다(정수 승격). 256으로 돌리는 단계가 빠졌는지 본다.
- `250 4`에 `3`처럼 엉뚱한 값이 나오면 → 입력부터 확인: `cerr << "[확인] p=" << static_cast<int>(p) << " c=" << static_cast<int>(c) << '\n';` 여기서 `p=50 c=53`이 보이면 `uint8_t`로 받아서 **글자 '2', '5'**를 읽은 것이다(직접 실행해 확인한 결과). 받는 자료형을 다시 본다.
- `-fsanitize=undefined`는 이 문제에서 아무것도 안 잡는다 — unsigned·8비트 넘침은 정상 동작이라서.

## AI 활용 단계

두 문제를 **혼자 다 푼 뒤에** 외부 AI에 이렇게 묻는다. 문제 2를 예로:

```
나는 C++ 코딩테스트를 공부하는 학생이야. 8비트 시퀀스 번호 문제를 혼자 풀었어.
[문제 2 설명, 제한 0 ≤ p, c ≤ 255 를 그대로 붙여넣기]
[내 코드 붙여넣기]
정답 코드를 새로 쓰지 말고, 다음만 번호 목록으로 알려줘:
1) 내 코드가 틀리는 입력이 있다면 그 입력값, 예상 출력, 내 코드의 실제 출력
2) uint8_t 두 개를 빼면 결과 자료형이 무엇인지, 그 근거(C++ 규칙 이름)
3) 내 코드를 16비트 시퀀스 번호(0~65535)로 바꾸려면 어디를 고쳐야 하는지
```

## 제출 방법

문제는 사이드바의 **코테 연습장**(문제 탭)에서 보고, 코드는 **VS Code**에서 짠다.

1. VS Code로 연 **coding-test 저장소 폴더**(맨 위)에 이번 회차 폴더를 넣는다: 연습장 **이번 회차 폴더 내려받기** → 터미널에서 `unzip -n $DL/coding-04-오버플로복습.zip -d ~/coding-test` (**가이드 9**).
2. VS Code에서 `문제N.cpp`를 열어 풀고 저장한다. 파일 맨 위 주석의 **걸린 시간·힌트 사용·AI 사용·막힌 점** 줄을 채우고, AI 메모는 파일 맨 아래 주석에 쓴다.
3. 터미널에서 문제 카드의 🖥️ 명령으로 확인한다. 틀리면 `cerr`로 값 찍기·`-fsanitize=undefined`로 고친다(가이드 3·4).
4. 저장소 맨 위(`cd ~/coding-test`)에서 `git add .` → `git commit -m "04회 practice, 문제1~2 풀이"` → `git push` (가이드 5). 03회도 풀었다면 `"03회 practice, 문제1~3 풀이"`로 **따로** 커밋한다.
5. 채팅에 **「푸시했어」** → GitHub에서 읽어 g++로 채점한다. 채점 후 고친 것은 `git commit -m "04회 문제N … 수정"`처럼 무엇을 고쳤는지 적어 올린다.
6. 면접 질문 답은 연습장 문제 탭 맨 아래 칸에 쓴다.

- 푸시를 못 한 날은 연습장 문제 아래 **저장한 파일 올리기**에 `.cpp`를 끌어다 놓고 「다 풀었어」.
- 읽다가 이해 안 되는 부분은 연습장 **이론 탭의 예측 칸**에 적거나 **공부 노트의 해당 섹션 아래 질문하기**로 물어보자(노트는 정답 코드는 알려주지 않는다).
